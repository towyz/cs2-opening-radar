# Backend

FastAPI service for uploading a CS2 demo, invoking the Go parser CLI, and returning the standard analysis result.

## Endpoints

- `GET /api/health`
- `POST /api/analyze`
- `POST /api/analyze-local`
- `POST /api/perfectworld/recent-dust2-demos`

`POST /api/analyze` expects multipart form data:

- `demo`: `.dem` file
- `steam64`: target Steam64
- `map_name`: defaults to `de_dust2`
- `window_seconds`: defaults to `30`

`POST /api/perfectworld/recent-dust2-demos` scans up to five recent `de_dust2`
matches for a Perfect World player. The verified player lookup is
`/user-info/match-list` with `uid=<Steam64>`; the app nickname such as
`PW8302744068` is not accepted by that endpoint. The Perfect World client then
requests demo availability through signed `POST /match-api/demo` calls and
downloads the returned demo URL.

The request signature is generated by the client native `SWAP_DATA` signer. The
backend calls it through the isolated bridge at
`tools/perfectworld_signer_bridge/signer_bridge.js`; set one of these environment
variables before starting the backend:

- `PERFECTWORLD_CLIENT_DIR`: Perfect World client install directory, for example
  the directory containing `plugin\gameaddon.node`
- `PERFECTWORLD_GAMEADDON_NODE`: explicit path to `plugin\gameaddon.node`
- `PERFECTWORLD_SIGNER_BRIDGE`: optional override for the bridge script path
- `PERFECTWORLD_SIGNER_NODE`: optional Node runtime used to run the bridge. The
  bundled Perfect World client module is 32-bit, so this must be a compatible
  32-bit Node/Electron runtime when `gameaddon.node` is x86.

For credentials, the backend first tries explicit request values and environment
variables. If none are supplied, it reads the already-running Perfect World
client login bridge at `http://127.0.0.1:55555/` using the client-approved
`https://match.wmpvp.com` origin, then falls back to recent local client logs.
The local bridge returns the current client token encoded with the same log
encoding used by Wmpvp logs.

Without an access token, the endpoint rejects the request with
`PERFECTWORLD_CREDENTIALS_REQUIRED`; without a working signer bridge, it can scan
recent matches but cannot request fresh demo URLs. Tokens and signed URLs are not
returned by the API.
